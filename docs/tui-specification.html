SPECIFICATION · TERMINAL USER INTERFACE

initd

Linux server administration, driven entirely from the keyboard. Target implementation: ratatui 0.29 + crossterm. Reference size 80×24, comfort size 120×40. Every mockup below is a real character grid — one glyph per cell, 16 ANSI roles, box-drawing borders, no sub-cell geometry.

00 · LOAD-BEARING DECISIONS
Nine choices the rest of the design depends on. Each exists to survive either a 24-row terminal, forty tasks, or a bad link into a server that is already on fire.
01 TWO NAMES PER TASK
Every task carries a long title ("Install and enable the SSH server") and a short label ≤ 20 cells ("Install and enable"). The tree draws labels, the detail pane draws titles. Truncation becomes the exception, not the rule, in a 30-cell column.
02 SELECTION IS A NODE ID
State keeps selected: NodeId plus an expanded-set; the flat visible list and the ListState index are derived each frame. Storing an index breaks the moment a fold above you changes the list length.
03 ONE BLOCK ON THE RIGHT
Detail and output live inside a single bordered block, separated by an inner Block::borders(TOP) with a title. Two stacked blocks would spend four of twenty-four rows on borders.
04 SEARCH LIVES ON THE STATUS ROW
Vim-style: / turns the status row into a prompt. Costs zero rows, needs no modal frame, and the filtered tree stays fully visible while you type.
05 FAILURE IS DATA, NOT A STATE
There is no Failed state. A finished run leaves a last_result on the task and the app returns to Browsing. Fewer modal states, fewer ways to trap the operator.
06 TWO TIERS OF CONFIRMATION
Ordinary destructive work asks y/N with N preselected. Lockout-class work (harden, port change) refuses a keypress and demands a typed word — a reflex cannot produce it.
07 A ROLLBACK WINDOW
After any change that can end your session, initd enters Verifying: 60 seconds, a live countdown, auto-revert unless you press K. The one design element that makes remote hardening genuinely safe.
08 OUTPUT IS A RING BUFFER, DRAWN ON A TICK
Child stdout appends to a 5 000-line VecDeque; the screen redraws at most every 100 ms. A chatty apt must never turn into one redraw per line over a 400 ms SSH link.
09 UNSUPPORTED STAYS VISIBLE
Tasks the host cannot run are dimmed, marked ·, and keep a full detail pane explaining the detected reason. Hiding them makes the tool look inconsistent between servers.
01 · SCREENS
All screens in this section are drawn at exactly 80×24 — the size that has to work. Row 1 is the identity header, rows 2–22 the body, row 23 the status row, row 24 the key bar.

WHY
A y/N prompt is answerable by muscle memory, and this operation can permanently end all access to a remote machine. So the safe answer is not merely the default — it is the only thing a single keypress can produce. Enter on an empty or mismatched field does nothing but restate the requirement; Esc leaves. The double-line red border is reserved exclusively for this class of dialog, so it is recognisable before the words are read. Everything above the field is evidence rather than warning prose: the key that will still work, with its fingerprint; the fact that your current session authenticated with it; that the config is validated with sshd -t first; that a backup exists at a named path; and that sshd is reloaded, not restarted. The last line is the countdown promise — the operator knows before consenting that a mistake self-heals in 60 seconds.

WHY
The state that turns an irreversible remote change into a reversible one. initd has already validated and reloaded; what it cannot know is whether you can still get in. 02 · GROWTH: ONE CATEGORY → SIX → NESTED
The tree is one widget with one behaviour at every stage: a depth-indented flat list of visible rows, derived each frame from the node graph and the expanded-set. Nothing in the layout changes between stage 1 and stage 3 — only how many rows the derivation produces.
STAGE 1 — 1 CATEGORY, 4 TASKS
Five rows in a twenty-row pane. The single category is auto-expanded on start and cannot be collapsed to an empty screen — folding the only root is allowed but the pane then shows the root plus a dim hint. No search: / is bound but reports "nothing to filter" below 12 tasks. Blank spacer rows between roots are on, because there is room.
STAGE 2 — 6 CATEGORIES, 33 TASKS
The shape that decides the design. All roots collapsed on start except the last one used (persisted in ~/.local/state/initd/ui.toml), so the screen opens as six rows, not thirty-three. Exactly one root expanded at a time by default — Enter on a collapsed root folds its siblings; Space is the non-exclusive toggle for people who want several open. Search becomes genuinely useful here and the key bar starts advertising it.
STAGE 3 — NESTED SUBCATEGORIES
Depth arrives with three cheap devices: 2-cell indent per level, dim vertical guides for open ancestors, and pinned ancestor rows when a parent scrolls off the top. Search stops being a convenience and becomes the primary way in: it flattens matches and appends a › breadcrumb, so a five-level tree is two keystrokes deep instead of five.

WHY
Modality is where TUIs break, so it is stated per state rather than left to the reader. Two shapes are easy to get wrong. Searching is semi-modal: printable characters go to the query, but Up/Down/Enter go to the list — that is what makes /por↓Enter possible, and it means the key handler must dispatch on key kind, not just state. Running is open, not modal: you can scroll, switch focus, even browse the tree, but every mutating key is refused with a status flash and only one task may run at a time. Implement the whole thing as one match (state, key) in a single function — a per-widget handler chain is how keys start leaking between modes. Finally, Verifying is the only state with a deadline that acts on its own; drive it from the worker's clock and treat UI death as "roll back".

NO RATATUI EQUIVALENT — COMPOSE FROM PRIMITIVES
TREE
There is no tree widget. Flatten to Vec<VisibleRow> each frame by walking the node graph and skipping children of collapsed nodes, build each row's indent, glyph, guides, label and flags as Line of Spans, and hand it to List + ListState. The flatten is O(visible) and cheap enough to redo per frame; caching it is the first thing that will desynchronise from the expanded-set. Pinned ancestors are rendered as a separate 1–2 row Paragraph above the List, with the List's area shortened accordingly.
TEXT INPUT
No input widget either. A Paragraph inside a bordered Block, plus state: String buffer, cursor as a grapheme index (use unicode-segmentation; byte indices will panic on the first non-ASCII key comment), and a horizontal scroll offset recomputed to keep the cursor inside the visible width. Draw the cursor either with a REVERSED single-cell Span or by calling Frame::set_cursor_position — prefer the real cursor, it is what screen readers and remote clients follow.
OUTPUT LOG
No log widget. Paragraph over a slice of a VecDeque<Line> (cap 5 000, drop from the front). With Wrap enabled the scroll offset is in wrapped lines, which Paragraph will not tell you — cache a wrapped-height count per source line, invalidated when the pane width changes, or you cannot implement "scroll to end" correctly. Follow mode is a bool: when true, offset is recomputed to the tail every frame; any scroll key sets it false.
09 · STATUS AND FEEDBACK
ONE AUTHORITATIVE PLACE
Row 23, left edge, a reversed pill: READY / RUNNING / DONE / FAILED / CANCELLED / VERIFY / CONFIRM / INPUT. Colour follows meaning (green, yellow, green, red, yellow, yellow, red, blue) and the word carries it alone if colour is absent. It is always in the same eight cells, so the operator's eye never searches.
IS IT STILL ALIVE?
Four signals, deliberately redundant: an elapsed timer that ticks every 250 ms; a one-character spinner beside it (ASCII - \ | /, not braille — braille is missing or double-width in too many fonts); the step counter; and, if a step produces no output for 10 s, an explicit dim line still running — no output for 12s appended to the log, refreshed in place. A frozen screen and a slow package manager must be distinguishable.
TRANSIENT MESSAGES
Refusals ("unsupported here", "a task is already running", "type harden to confirm") flash on row 23 for 2 s as Option<(String, Instant)>, overriding the pill's message but never the pill. No toasts, no overlays: a message that occludes content is unacceptable when the content is a running log.
AFTER THE FACT
Completion is not ephemeral. The task's row keeps a result glyph (✓ / ✗) for the session, the detail pane opens on the last result with its duration, and a full transcript is written to /var/log/initd/<task>-<timestamp>.log — reachable with e. Terminals scroll away and SSH sessions die; the log is the record.
CANCELLATION IS HONEST
Ctrl-C during a step that is mid-write does not pretend to abort instantly: the status shows CANCELLED only once the child has exited and the step's own rollback has run, and the log states which steps were applied and which were not. A tool that lies about having stopped is how half-configured servers happen.
BAD CONNECTIONS
Redraws are coalesced to at most 10 per second and only when something changed; output arrives as batched lines per tick. No progress bar animates for its own sake, no spinner spins when nothing is running, and a full-screen redraw is available on Ctrl-L for when the link corrupts the screen — which it will.
